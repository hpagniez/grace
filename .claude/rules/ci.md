# CI and automation

Decided in [ADR 0007](../../docs/decisions/0007-github-actions-ci-cd-on-the-free-private-plan.md); merging on green in [ADR 0011](../../docs/decisions/0011-merge-labelled-prs-when-ci-is-green.md); e2e on CI only for PRs into `main` in [ADR 0017](../../docs/decisions/0017-e2e-on-ci-only-for-prs-into-main.md); the public repo in [ADR 0018](../../docs/decisions/0018-make-the-repository-public.md); `perf` in [ADR 0023](../../docs/decisions/0023-run-lightly-as-a-release-requirement.md). The repo is public on GitHub Free: Actions minutes on standard runners are free. A ruleset on `main` and `develop` blocks force-pushes and deletion, takes changes only through a PR merged with a merge commit, and requires `checks` to pass. Workflows may use only GitHub-owned actions pinned to a full commit SHA, plus SignPath's signing action in `release.yml` ([ADR 0024](../../docs/decisions/0024-sign-grace-exe-with-signpath-foundation.md)). Releases are immutable: once published, their tag and zip never change.

- The repository's Actions settings list the one allowed SignPath SHA. A PR that changes the SHA of `SignPath/github-action-submit-signing-request` in `release.yml`, Dependabot's too, must be matched by the owner (the call needs admin) before the next tag, or that tag's release ends in a `startup_failure` that cannot be rerun ([#202](https://github.com/hpagniez/grace/issues/202)). The call replaces the list; check it with the same path and `gh api`: `gh api -X PUT repos/hpagniez/grace/actions/permissions/selected-actions -F github_owned_allowed=true -F verified_allowed=false -f 'patterns_allowed[]=SignPath/github-action-submit-signing-request@<full SHA>'`. Agents never change these settings: the PR body asks the owner.
- Merge only when `checks` and `test` are green and `perf` has finished with success. The ruleset enforces only `checks`.
- `test` and `perf` start on every PR. Their first job, `scope`, runs `cargo xtask scope` ([spec](../../docs/specs/2026-11-12-ci-scope.md)), and each heavy job runs only for the areas the PR changes: `electron` runs `unit`, `e2e` and `perf`; `gpui` runs `rust`; `scripts` runs `unit`. The table of paths is in `crates/xtask/src/scope.rs`; a path it does not know runs everything, and so does a run by hand. Marking a PR into `develop` ready on a commit that already passed the workflow runs no heavy job again: that trigger is there for the bots' PRs, which no push started. `cargo xtask scope origin/develop` says what a branch will run.
- A PR that changes a heavy job's steps, which its own scope may skip, runs that workflow by hand once before it merges (`gh workflow run <file> --ref <branch>`): Dependabot's `github-actions` PRs too.
- Every PR that changes Electron Grace gets a comment from the `perf` workflow: the PR against its base, measured by `npm run bench`. Read it. When it shows a measure worse than base beyond its noise margin, say why in the PR body. A worse number never blocks a merge, but the PR body explains it.
- The limits are in `bench/limits.json`. Lowering one is an ordinary commit. Raising one needs a new decision record: `scripts/check-pr.mjs` fails a PR that raises a limit without adding a file under `docs/decisions/`.

| Workflow | When | What it runs |
|---|---|---|
| `checks` | Every PR to `develop` or `main`, except a `release/*` or `hotfix/*` merge back into `develop` (Linux); by hand, as a PR into `develop` | lint, typecheck, `npm audit --audit-level=high`, `cargo xtask check-rules` (the size and globs of the agent rules files, and the docs' frontmatter and indexes), clippy and `cargo test` of `crates/xtask`, `cargo xtask check-pr` (the PR body's `Tier:` line and what follows from it: a Small PR stays small, a Feature or Project PR names its issue, spec and plan, and a Project's plan has its `## Slices`; a PR that closes its issue names a `built` spec and plan; a `feat` or `fix` comes with a test; a new script that is not Rust says why; no session link; commit headers; branch target; a release or hotfix check record's `## Public docs`), `scripts/check-pr.mjs` (that record's `## Performance` section, a raised limit in `bench/limits.json`). It runs again when the PR body is edited |
| `test` | Every PR, except a `release/*` or `hotfix/*` merge back into `develop` (Windows; `scope` on Linux); by hand | Jobs on their own VMs ([ADR 0016](../../docs/decisions/0016-windows-tests-in-parallel-jobs.md)), each only for its areas: `unit` runs `npm test` in two halves (half 2: the files listed in `test.yml`, half 1: every other file); `e2e` runs `npm run e2e` as two Playwright shards only on PRs into `main` that are not drafts, and on runs by hand (`gh workflow run test.yml --ref <branch>`); `rust` runs clippy, `cargo test`, `patches/check.sh` and GPUI Grace's e2e (on Windows only on PRs into `main` and by hand); `gpui-idle`, only by hand, runs `npm run bench:gpui` on Windows and fails when GPUI Grace wakes more than 5 times a second minimised |
| `perf` | Every PR, except a `release/*` or `hotfix/*` merge back into `develop` (Windows; `scope` on Linux); by hand (the chosen ref against `develop`) | Only for `electron`: builds the PR's base and its merge ref on one VM and runs `npm run bench` on both in PR mode, about 20 minutes. Posts the table as one PR comment, updated on every push, and in the job summary (summary only for forks and Dependabot). Fails only when it cannot build, measure or post, never on a worse number |
| `merge-when-green` | `checks`, `test` or `perf` finishes; a PR into `develop` is labelled or marked ready (Linux) | Merges a PR into `develop` from a branch of this repo (never a fork) that has the `merge-when-green` label and is not a draft, once `checks` and `test` passed and `perf` finished with success on its head commit (a run whose jobs `scope` skipped is a success). A back-merge from `release/*` or `hotfix/*` needs those runs from its PR into `main`, with every `e2e` step that ran passed and none skipped |
| `release` | Push of a `vX.Y.Z-rc.N` tag (a plain `vX.Y.Z` tag runs nothing); by hand | Tag must match `package.json`; `npm run make`; SignPath signs `Grace.exe` once a person approves, when the `SIGNPATH_ORGANIZATION_ID` variable is set ([ADR 0024](../../docs/decisions/0024-sign-grace-exe-with-signpath-foundation.md)); GitHub pre-release with the zip. By hand: build and test-sign, publish nothing |
| `vendor-updates` | Weekly, and by hand | Draft PR per newer Temurin 21 JRE or Karate 2.x (pins in `scripts/vendor.json`, [ADR 0012](../../docs/decisions/0012-weekly-draft-prs-for-the-bundled-jre-and-karate.md)); a Karate bump re-records the event fixtures. Mark it ready for review to run CI (unit tests, no e2e) |
| `cargo-updates` | Weekly (Tuesday), and by hand | PR `feature/bump-cargo-<date>` moving the GPUI set and Rust to the newest releases, the Windows patches rebased, and `Cargo.lock` (`scripts/bump-cargo.mjs`, [ADR 0032](../../docs/decisions/0032-keep-the-gpui-set-rust-and-cargo-lock-current.md)); then runs `checks`, `test` (Windows e2e and `gpui-idle` included) and `perf` on it by hand, and merges it once all three pass ([ADR 0033](../../docs/decisions/0033-merge-the-weekly-cargo-bump-prs-on-green.md)). A failed run leaves the PR open with a comment, and the run fails: fix the branch, run the failed workflow again by hand, then merge as any PR. A patch that no longer applies gets an issue, and the rest still moves |

Dependabot opens grouped update PRs into `develop` monthly, plus security PRs when an alert appears. It does not see the JRE and Karate pins in `scripts/vendor.json`: `vendor-updates` bumps them (`npm run vendor:bump -- <jre|karate>` by hand). The ECJ pin there, a build tool only, is bumped by hand ([ADR 0025](../../docs/decisions/0025-compile-the-debug-listener-with-ecj-on-the-bundled-jre.md)). Nor does it watch Cargo: `cargo-updates` moves the GPUI set, Rust and `Cargo.lock` ([ADR 0032](../../docs/decisions/0032-keep-the-gpui-set-rust-and-cargo-lock-current.md)).

## Issues and the project board

- To change an issue's `Spec:` line: `gh issue edit <N> --body-file -` replaces the whole body, so start from the current one (`gh issue view <N> --json body --jq .body`), change only that line, and pipe the full body back.
- For a feature built over several PRs, move its card to `building` when its first building PR (not a spec-only PR) opens: `gh project item-add 2 --owner hpagniez --url <issue URL> --format json --jq .id` gives the item ID, then `gh project item-edit --id <item ID> --project-id PVT_kwHOAka2MM4BpJIV --field-id PVTSSF_lAHOAka2MM4BpJIVzhnmDmA --single-select-option-id 47fc9ee4`. Both calls need a token with the `project` scope (`gh auth refresh -h github.com -s project`) ([ADR 0014](../../docs/decisions/0014-backlog-in-github-issues-and-a-project.md)).

## The script crate

`crates/xtask` holds Grace's scripts ([AGENTS.md](../../AGENTS.md#graces-own)). A `SessionStart` hook in `.claude/settings.json` runs `cargo xtask tidy`, which reports leftovers and never fails; the same file's `permissions.deny` refuses a command that makes a junction or a symbolic link, or force-pushes. Those rules match the command as written: a guardrail, not a wall. It is under `crates/` but is not GPUI Grace: `checks` runs its clippy and tests, `cargo xtask scope` gives it no area, and a PR that changes only it needs no Windows run by hand. Before pushing it: `cargo fmt --all --check` after the last edit, `cargo clippy -p xtask --all-targets -- -D warnings` and `cargo test -p xtask`.
