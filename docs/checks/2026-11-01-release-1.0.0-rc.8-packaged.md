# Packaged app check: release 1.0.0-rc.8

Date: 2026-11-01
Branch: `release/v1.0.0-rc.8` at fef01e0 (`develop` after #189, plus the version bump, the README and its screenshots)
Machine: Windows 11 Pro 10.0.26300 (x64), Ryzen 7 5800X, 32 GB, Node 24, second screen 2560x1440. No Java on the machine.
Features since 1.0.0-rc.7: Grace runs lighter. Idle, the console cursor no longer blinks, so the window costs next to no CPU (#170, #147). Java runs at below-normal priority (#148) and with a 2 GB heap that starts at 64 MB (#149). A success notice looks like a success (#158), and the update switch reads each process's path once (#160, #162). Also Electron 45.1.0 (#197), Solid 2.0.0-rc.19 (#196), minimatch 11.0.3 under the asar packager (#184), and the `perf` workflow and release benchmark (#147). The `release` workflow can sign `Grace.exe` with SignPath (#176), but its `sign` job stays skipped until SignPath Foundation accepts the project. Bundled Temurin JRE 21.0.12.1+1 and Karate 2.1.4 are unchanged.

Playwright cannot drive the packaged exe (ADR 0004), so this check covers what only packaging can break.

## Public docs

- `README.md`, checked against 1.0.0-rc.8:
  - **Made for long sessions** now says that Grace uses next to no CPU while it waits, and that Java runs at below-normal priority with a 2 GB memory cap (#147, #148, #149).
  - The roadmap dropped lighter runs (#148, #149), both shipped, for less CPU spent by Java's compiler during a run (#179).
  - The code signing policy still holds: signing waits for SignPath Foundation, so this release is unsigned. The install and update note, the status badge and the other features still hold.
- Screenshots in `docs/images/`: retaken with `npm run screens:readme`. They differ from 1.0.0-rc.7's only in the version in the status bar and the timings; the alt texts still fit.
