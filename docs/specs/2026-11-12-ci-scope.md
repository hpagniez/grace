# CI by what a PR changes

Issue: [#363](https://github.com/hpagniez/grace/issues/363). Follows the way of working ([#356](https://github.com/hpagniez/grace/issues/356)).

## Why

`test` and `perf` start on every PR except one that changes only `docs/**` and `*.md`. #362 changed `.claude/`, `.github/`, `crates/xtask/`, `docs/`, `scripts/` and `AGENTS.md`: it ran `perf` (16 minutes on Windows, measuring an Electron Grace it did not change), the GPUI build on Linux and Windows, and then a 65-minute Windows run by hand, because the rules ask for one on any PR that changes `crates/`. The docs-only rule lives in three places: the `paths-ignore` of `test.yml` and `perf.yml`, and a bash copy in `merge-when-green.yml`. The owner wants less time spent, with the same checks where they matter, and the rule simple and in one place.

## Requirements

1. One rule, in Rust, says which areas a diff touches: `cargo xtask scope [<base>]` reads `git diff --name-only <base>...HEAD` and prints `electron=`, `gpui=` and `scripts=` lines, `true` or `false`, for `$GITHUB_OUTPUT`. Without a base (a run by hand) every area is `true`.
2. The rule is a table of path patterns, first match wins; a pattern is a folder (`src/`), a file (`package.json`) or a suffix (`*.md`):

   | Paths | Areas |
   |---|---|
   | `*.md`, `docs/`, `.claude/`, `.github/`, `crates/xtask/`, `LICENSE`, `.gitignore`, `.prettierignore`, `.oxlintrc.json`, `rustfmt.toml`, `.signpath/` | none: `checks` covers them, or nothing runs them on a PR |
   | `src/renderer/`, `src/index.css`, `index.html`, `assets/`, `test/`, `listener/`, `package.json`, `scripts/vendor.json`, `scripts/fetch-vendor.mjs` | `electron` and `gpui`: GPUI Grace's tests read them (icons, theme, startup screen, fixtures, versions, the JRE and jar) |
   | `src/`, `e2e/`, `bench/`, `package-lock.json`, `tsconfig.json`, `forge.config.mts`, `vite.*`, `vitest.config.mts`, `playwright.*` | `electron` |
   | `crates/` | `gpui` |
   | `patches/`, `Cargo.toml`, `rust-toolchain.toml` | `gpui` and `scripts`: `scripts/bump-cargo.test.ts` reads them |
   | `Cargo.lock`, `.cargo/`, `scripts/e2e-gpui.sh` | `gpui` |
   | `scripts/` | `scripts`: the Node scripts, whose tests are in `npm test` |
   | anything else | every area |

   A path no row knows runs everything: a new file costs minutes, never a missed check.
3. `test.yml` and `perf.yml` drop `paths-ignore` and always start. Their first job, `scope`, runs the command on Linux (about 30 seconds) with the PR's merge commit's first parent as the base; it keeps the release and hotfix back-merge skip, so a back-merge's runs stay skipped as today. The heavy jobs `need` it:
   - `unit`: `electron` or `scripts`
   - `e2e`: `electron`, and as today only on PRs into `main` and by hand
   - `rust`: `gpui`
   - `perf`: `electron` (and `gpui` too once the bench judges GPUI Grace, #334)
   - `gpui-idle`: unchanged, by hand only
4. A run whose heavy jobs are all skipped ends in success, so `merge-when-green` needs no path rule: its two docs-only loops go. Its back-merge check accepts a run with no `e2e` step (a hotfix that changes no app), and still refuses one whose `e2e` step was skipped (a draft).
5. `checks`, required by the ruleset and unchanged in when it runs, adds `cargo clippy -p xtask` and `cargo test -p xtask`: the script crate has no dependency, so they take seconds on Linux, and a PR that changes only `crates/xtask/` needs nothing else.
6. Runs by hand (`gh workflow run`, and the ones `cargo-updates` starts and waits for) run everything, as today.
7. The rules files: the by-hand Windows run is for a PR whose `gpui` area is true (`cargo xtask scope origin/develop` says), not for `crates/xtask`; a PR that changes a heavy job's steps in a workflow runs that workflow by hand once, since its own scope skips them; `ci.md`'s table says when each job runs.

## Acceptance checks

- Unit tests of the table: a docs-and-xtask diff touches nothing; `src/renderer/x.tsx` touches `electron` and `gpui`; `src/main/x.ts` only `electron`; `crates/grace/x.rs` only `gpui`; `scripts/bump-pr.mjs` only `scripts`; an unknown top-level file touches all; no base touches all; an empty diff touches nothing.
- This PR's own CI: `scope` reports all `false`, and `unit`, `rust`, `perf` and `e2e` are skipped; `test` and `perf` end in success; `checks` runs the xtask clippy and tests.
- A run of `test.yml` by hand on this branch starts `unit`, `rust`, `e2e` and `gpui-idle` (cancelled once started: it proves the scope, not the suites).
- `merge-when-green` merges this PR once labelled (its copy on `develop` finds the runs green).

## Approaches

- **Chosen: a scope job in each workflow, the rule in `cargo xtask scope`.** One rule in Rust with tests; a few lines of YAML per workflow. Costs a 30-second Linux job per workflow per push.
- `paths` / `paths-ignore` per workflow: no code, but a skipped workflow posts no run, so `merge-when-green` must keep its own copy of the paths, and one workflow cannot skip some jobs and run others.
- One reusable workflow (`workflow_call`) holding the scope job: removes the job's duplication in two files, adds a file and the plumbing of its outputs. Not worth it for a four-step job.

## Left to the builder

Pattern matching stays minimal (folder, file, suffix, a `*` at the end of a file name); no glob crate. On a git error the command fails the job rather than guessing.

## Cost

Cost: none to the app. CI: a docs-and-scripts PR such as #362 saves about 21 Windows minutes and 13 Linux minutes per push (`perf` 16, `rust` 5 and 13), plus the 65-minute Windows run by hand; it adds about 1 Linux minute (two `scope` jobs).
