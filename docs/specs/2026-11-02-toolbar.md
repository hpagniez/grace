# A toolbar that stays readable with a long project path

Date 2026-11-02. Status: approved. Covers [#81](https://github.com/hpagniez/grace/issues/81).

## Intent

A project often lives deep in a disk: `C:\Users\<name>\OneDrive - <company>\Documents\source\repos\…\payments-gateway-contract-tests`. The toolbar then gets crowded and hard to read. Measured in the packaged app (rc.8) with such a path:

- At 1440, 1200 (the default window) and 1000 px, the folder name is already cut (`payments-gateway-contract…`) while the path beside it still shows its tail, which is that same folder name (`…\payments-gateway-contract-tests`). The path and the name share the room in proportion to their shrink factors (10 to 1), so the name loses pixels before the path is gone.
- At 760 px (the window's minimum) the path and the layout chip are gone and the name reads `payments…`: the boxes and buttons leave it about 90 px.

The fix gives the folder name the toolbar's room and moves the full path to the status bar, where it has most of the window's width.

## Who and what success looks like

Someone with Grace open all day beside an IDE, with a project in a deep folder, in a window of any width from 760 px up. Success: they read which project is open at a glance at every width, the whole name at the default 1200 px and up, and its start and end at the minimum; the full path is always one glance away at the bottom of the window.

## Goals, non-goals, anti-goals

- Goals: the folder name shows whole whenever the toolbar has room for it; the path stops repeating the name; the path keeps the drive and the project folder in sight at every width; every button keeps its size, its place and its name.
- Non-goals: clicking the path (to open the folder or copy it); a second toolbar row; changing the buttons' narrow rule (icon only below 1280 px).
- Anti-goals: any timer, poll or measuring loop to lay out the toolbar (idle costs nothing); text that wraps or overlaps; a button that leaves the window at 760 px.

## Constraints

- UI conventions in `AGENTS.md`: semantic colour tokens only, cut text through `Cut` (its tooltip only when the text is cut), shared class strings in `buttons.ts` and `ui.ts`, no `title=`.
- The window's minimum is 760 px (`src/main.ts`); its default is 1200 × 800. Both are below 1280 px, where the buttons are already icon only.

### What exists today

`src/renderer/Toolbar.tsx`: the Home button, then a container with the folder name (end-cut), the layout chip (hidden below 1280 px once the container is under 160 px) and the full path (cut from its start with `direction: rtl`), then the `Env` and `Threads` boxes with their visible words, `Properties…`, Refresh, `Open…`, `Report`, `Re-run failed`, `Cancel` and `Run all` ([premium UI spec R13](2026-10-29-premium-ui.md)). The status bar (`src/renderer/StatusBar.tsx`) is right-aligned: the update marker, `Update`, the version and `Settings`; its left end is empty.

## Approaches considered

Shown to the owner on the packaged app at 1440, 1200 and 760 px, with a long path.

1. **A: the path stays in the toolbar.** It shows only the parent folder (no repeated name), cut in the middle, and gives way entirely before the name loses a pixel. At 760 px there is still no room for it, and above that it gets 100 to 250 px.
2. **B: the path moves to the status bar. Chosen.** The toolbar holds the name and the chip; the status bar's empty left end takes the full path, with 500 px or more at the minimum width. Its cost: the path sits away from the name, at the bottom.

Freeing room for the name at 760 px: hiding the words `Env` and `Threads` below 1280 px, as the button labels already are, gives it about 90 px more. **Chosen** by the owner, over keeping the words.

## Requirements

### R1. The project in the toolbar

1. After the Home button: the folder name (14 px, 500) and the layout chip. The path is no longer in the toolbar.
2. As the room shrinks, the chip goes first, whole (it is never cut); then the name is cut in the middle: its start gives way behind an ellipsis, its last 12 characters stay. When even those do not fit, they are cut at their end.
3. A cut name shows the whole name in a tooltip; a name that fits has none.

### R2. The path in the status bar

1. While the project view shows (a project is open or opening), the status bar's left end holds the project's full path, in the 12 px mono `muted`, as text. The home screen shows none.
2. When it does not fit, it is cut in the middle: the folders before the project folder give way behind an ellipsis, and the project folder's name stays. When that alone does not fit, it is cut at its end.
3. A cut path shows the full path in a tooltip; a path that fits has none.
4. The status bar's own items keep their size; the path takes the room left.
5. The path keeps `data-testid="project-path"`, and its text is the full path, characters in order.

### R3. Env and Threads below 1280 px

1. Below 1280 px the words `Env` and `Threads` leave sight, like the button labels: they stay the boxes' accessible names, and show in a tooltip beside the box on hover and keyboard focus.
2. From 1280 px up they show, and the boxes have no tooltip.

### R4. The rest of the toolbar

Its order, sizes, buttons, test ids, labels, disabled rules and narrow rule stay as premium UI R13 and today's code have them. At 760 px every button is whole inside the window and the toolbar does not overflow.

This spec replaces the project part of premium UI R13.1 (name, chip and path) and adds the path to the status bar of R21.

## Cost

- Memory and CPU: two more `matchMedia` listeners (the `Env` and `Threads` boxes), which run only when the window crosses 1280 px. The middle cuts and the chip giving way are CSS (two `truncate` spans per cut, a wrapping row); nothing measures or polls. `Cut` measures only when a tooltip is about to show, as today.
- Idle: zero CPU, as today: no timer, poll or animation.
- Start and response: no change beyond a few more elements in the status bar.
- Size: a few hundred bytes of code and CSS; no dependency.

## Design decisions already made

- B over A, and the words `Env` and `Threads` hidden below 1280 px: the owner's choice, on the packaged app.
- The chip gives way before the name (proposed with B): which project is open matters more than its layout, which shows again as soon as the room returns.
- The name's tail is a fixed 12 characters, so it always fits at the minimum width; the path's tail is the project folder, which is what a reader looks for.
- The tooltips of `Env` and `Threads` go to the left of the box, where the word was, and so stay clear of the environment suggestions under the box.

Scenarios run in Vitest (jsdom) unless marked **(e2e)**, which run in Playwright against the built app.
