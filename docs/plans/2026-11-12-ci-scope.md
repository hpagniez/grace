# CI by what a PR changes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `test` and `perf` run each heavy job only for the areas of the repository a PR changes, from one rule in `cargo xtask scope`.

**Architecture:** A new module `crates/xtask/src/scope.rs` maps changed paths to areas through a first-match table; `run` gets the paths from git and prints `name=true|false` lines. Each of `test.yml` and `perf.yml` gets a first Linux job, `scope`, whose outputs gate the heavy jobs. `merge-when-green` loses its docs-only loops; `checks` gains the xtask clippy and tests.

**Tech Stack:** Rust 1.99.1, standard library only; GitHub Actions YAML.

**Spec:** [docs/specs/2026-11-12-ci-scope.md](../specs/2026-11-12-ci-scope.md)

## Global Constraints

- Tier: Feature. One PR into `develop`, `Closes #363`, body with `Tier: feature`, the spec and the plan.
- `crates/xtask`: `#![forbid(unsafe_code)]`, no dependency, git started through `rules::git(rules::root(), args)` with an argument list.
- Workflows use only GitHub-owned actions pinned to a full SHA, as the files already do.
- The release and hotfix back-merge skip stays: on such a PR every job of `test` and `perf` is skipped, `scope` included.
- A run by hand (`workflow_dispatch`) runs every job it runs today.
- `.claude/rules/ci.md` and `.claude/rules/gpui.md` keep their `paths:` front matter.

## Review Focus

1. **A path no row knows** (a new top-level file, `.gitattributes`): every area true. Test `an_unknown_path_touches_every_area`.
2. **A Markdown file inside an app folder** (`src/README.md`, `patches/README.md`): no area, as today's `**/*.md`. Test `markdown_anywhere_touches_nothing`.
3. **A prefix that is not a folder** (`src-old/x.ts`, `docs-old/a.txt`): matched by no folder row, so every area. Test `a_folder_row_matches_only_that_folder`.
4. **A back-merge's runs turning green** because `scope` ran: `merge-when-green` would then find a run with no `e2e` step. `scope` carries the back-merge `if:`, so the run stays skipped (checked by reading the YAML in Task 2, Step 5).
5. **git failing** (base not fetched): the command exits non-zero, the heavy jobs are skipped and the run fails, so `merge-when-green` does not merge. Test `run_fails_when_git_fails`.

### Task 1: `cargo xtask scope`

**Files:**
- Create: `crates/xtask/src/scope.rs`
- Modify: `crates/xtask/src/main.rs`

**Interfaces:**
- Produces: `pub const ELECTRON: u8 = 1; pub const GPUI: u8 = 2; pub const SCRIPTS: u8 = 4; pub const ALL: u8 = 7;`, `pub fn areas(path: &str) -> u8`, `pub fn outputs(areas: u8) -> String` (`"electron=true\ngpui=false\nscripts=false\n"`), `pub fn scope(base: Option<&str>, git: &dyn Fn(&[&str]) -> Option<String>) -> Result<u8, String>` (no or empty base: `ALL`; else the OR of `areas` over `git diff --name-only --no-renames <base>...HEAD`; git failing: `Err`), `pub fn run(base: Option<String>) -> u8`.
- A row is `(pattern, areas)`: a pattern ending in `/` matches that folder, one starting with `*` a suffix, one ending in `*` a prefix of a top-level file name, any other an exact path. The table is the spec's, in the spec's order.
