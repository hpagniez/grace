# Faster CI Implementation Plan

**Goal:** The `test` workflow runs unit and e2e tests as four parallel Windows jobs, each suite split in two, so a ready PR takes about 7 minutes and a draft PR about 5.

**Architecture:** `test.yml` gets a `unit` job (matrix `half: [1, 2]`) and an `e2e` job (matrix `shard: [1, 2]`). Half 2 of `unit` runs a fixed list of runner test files; half 1 excludes that list through `UNIT_EXCLUDE`, read by `vitest.config.mts`. The e2e step passes `--shard` to Playwright. `merge-when-green.yml` requires every `e2e` step to pass.

**Spec:** [docs/specs/2026-10-28-faster-ci.md](../specs/2026-10-28-faster-ci.md). **Decision:** [ADR 0016](../decisions/0016-windows-tests-in-parallel-jobs.md).

## Global Constraints

- No test name, body or assertion changes.
- Actions stay pinned to the SHAs `test.yml` uses today.
- Commits follow ADR 0003, one logical change each.
- Never run `npm test` and `npm run e2e` at the same time (AGENTS.md).
