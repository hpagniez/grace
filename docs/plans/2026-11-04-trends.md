# Trends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A trend strip at the top of the History tab: per stored run of the picked environment, the pass rate and the time per test of the tree selection.

**Architecture:** A pure `findTrend` in main (like `findFlaky`) turns the listed runs, the tree, a selection key and the environment into at most 20 `TrendPoint`s. The window asks for them through a new `trend(key)` IPC call, only while the History tab shows, one request at a time. A `Trends` component draws plain HTML columns with token classes.

**Tech Stack:** Electron main + preload IPC, SolidJS 2 RC, Tailwind v4 tokens, Vitest, Playwright.

**Spec:** [docs/specs/2026-11-04-trends.md](../specs/2026-11-04-trends.md)

## Global Constraints

- Solid 2 only (AGENTS.md "Solid 2 rules"): `createEffect(compute, apply)`, `onSettled`, `For` keyed gets `(item, index)`; no `classList`, no `title=`.
- Colours only through tokens: `bg-passed`, `bg-failed`, `bg-muted`, `border-line`, `text-muted`. No raw palette class, no `dark:`, no new token (`palette.test.ts`, `tokens.test.ts`).
- Tooltips only through `Tooltip`. No animation or transition on the strip.
- Nothing runs while the History tab is not shown; no timer anywhere.
- No dependency.
- Commits: Conventional Commits, subject ≤ 72 chars, body `Part of #93`, ending with the Claude Code attribution lines.

## Review Focus

1. A selected node that a refresh removed, or a key main does not know: main answers `[]`, the strip says "No stored run ran these tests", nothing throws. (Task 1 test "unknown key".)
2. A run whose stored tests have no `durationMillis` (records written before durations): pass bar drawn, no time bar, no "NaN". (Task 1 "meanMillis null", Task 4 "no time bar".)
3. A project of thousands of tests: matching uses a once-per-request index, never `resolveNode` per stored test. (Task 1 test that a renamed key still resolves by identity through the index; reviewer checks no per-test tree walk.)
4. Selection changing faster than main answers: one request in flight, the last selection wins, stale answers dropped. (Task 4 "coalesces".)
5. Closing the project or clearing history while History shows: the strip leaves with the empty state and no request is sent for an empty history. (Task 4 "no runs, no strip".)

### Task 1: `findTrend` in main

**Files:**
- Create: `src/shared/trends.ts`, `src/main/trends.ts`
- Test: `src/main/trends.test.ts`

**Interfaces:**
- Produces, in `src/shared/trends.ts` (no Node imports, header comment like `shared/flaky.ts`):
  ```ts
  /** One stored run as the trend strip shows it, for the selection asked about. */
  export interface TrendPoint {
    id: string;           // run folder id
    startedAt: number;
    passed: number;       // counted tests that passed
    failed: number;       // counted tests that failed
    total: number;        // tests under the selection in the current tree
    meanMillis: number | null; // mean durationMillis of counted tests that have one
  }
  ```
- Produces, in `src/main/trends.ts`:
  `findTrend(runs: ListedRun[], tree: TestNode | null, key: string | null, env: string | null): TrendPoint[]` — oldest first.

- [ ] **Step 1: Write the failing tests** in `src/main/trends.test.ts`, reusing the `node`/`tree`/`stored`/`run` fixture shapes of `src/main/flaky.test.ts` (copy them; add `durationMillis` to `stored`). Runs are passed newest first, as `listRuns` gives them. Cases:
  - "the whole tree, oldest first": two runs (startedAt 2 then 1), `key` null → `[{ id: "run-1", … }, { id: "run-2", … }]` with `total` = 4 (two scenarios, two rows).
  - "a selection counts only its tests": run with `one` passed and `two` failed; `key` `"s:tests/a.feature#1"` → `passed 1, failed 0, total 1`; `key` `"f:tests/a.feature"` → `passed 1, failed 1, total 4`; `key` `"o:tests/a.feature#3"` with a stored row → counts the row, `total 2`.
  - "a run with no counted test has no point": run of `two` only, key of `one` → `[]`.
  - "notRun and interrupted do not count": a run of `one` `notRun` and `two` `interrupted` → `[]` for `key` null.
  - "a debug run is left out": `{ debug: true }` → no point.
  - "only the picked environment": runs with `env: "dev"` and `env: "qa"`; `env` `"dev"` → only the dev run; `env` null → neither.
  - "meanMillis": durations 1000 and 2000 → `1500`; one test without duration and one of 300 → `300`; none with a duration → `null`.
  - "a renamed key still resolves": tree whose `one` moved to section 5 (`tree([["one", 5], ["two", 2]])`), stored key `#1` → counted under `"s:tests/a.feature#5"`.
  - "an ambiguous name does not count": tree with two scenarios named `one` and none at the stored key → `[]`.
  - "unknown key, no tree": `key` `"s:nope#1"` → `[]`; `tree` null → `[]`.

- [ ] **Step 2: Run** `npx vitest run src/main/trends.test.ts` — Expected: FAIL, module not found.

- [ ] **Step 3: Implement** `TrendPoint` and `findTrend`. Build two maps from one walk of the tree: key → leaf node, and `JSON.stringify([file, kind, name])` → leaf nodes. A stored test resolves to `byKey.get(key)` when that node's name equals the test's, else to the one node of its identity, else nothing (the rule of `resolveNode` in `src/main/karate/tree.ts`, whole tree). The selection is `findNode(tree, key)` (root when `key` is null); its leaves are `new Set(leafKeys(node))`. Skip runs with `debug` or `env !== env`; count tests with status `passed`/`failed` whose resolved node is in the set; drop a run with nothing counted; reverse to oldest first.

**Interfaces:**
- Consumes: `Api.trend`, `TrendPoint`, Task 3's labels, `Tooltip`, `formatMillis`.
- Produces: `Trends(props: { state: AppState; api: Api })`. Test ids: `trends` (the `section`, `role="group"`, `aria-label` `` `Trend of ${caption}` ``), `trends-caption`, `trends-pass-label`, `trends-time-label`, `trends-time-max`, `trends-none`, `trend-run` (one `button` per point, `data-id` = run id, `aria-label` = `trendTip`), `trend-passed`, `trend-failed`, `trend-time` (the bars).

Layout (spec R1.4, R3): `px-3 py-2`, caption line (`text-xs text-muted`, cut with `Cut` when long), then a two-row grid: labels column (`text-xs`, `tabular-nums`) and the columns. Pass row and time row each `h-6` with `border-b border-line` as baseline, `gap-1` (4 px) between columns, columns `w-3`. Pass bar: `flex h-full flex-col gap-0.5 overflow-hidden rounded-t`, children only for a non-zero share, failed above passed, each `style={{ "flex-grow": count }}`. Time bar: `rounded-t bg-muted`, height `max(2px, meanMillis / max * 100%)`, absent when `meanMillis` is null. `trends-time-max` shows `formatMillis(max)` right of the time row. Before the first answer, the frame without columns; with an empty answer, `trends-none` "No stored run ran these tests", same height.

Fetching (spec R5): one `createEffect` whose compute reads `state.selected`, `state.history`, `state.tree` and `state.env?.env`, and whose apply calls `ask()`. `ask` keeps `busy`/`again` flags: while busy it only sets `again`; when an answer comes and `again` is set, it drops that answer and asks again with the selection then current; otherwise it sets the points. A `live` flag cleared on cleanup drops answers after unmount. Click on `trend-run`: `document.querySelector(`[data-testid="history-row"][data-id="${id}"]`)?.scrollIntoView({ block: "nearest" })`.
